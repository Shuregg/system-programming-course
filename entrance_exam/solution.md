# Вступительное задание: свёртка матриц

Решение — [matrixconv.c](matrixconv.c), открытые тесты — [open-tests/](open-tests/).

## 1. Постановка задачи

### Запуск

Программа на C принимает имя входного файла через флаг `-i` и имя выходного через `-o`:

```bash
./prog -o output.dat -i ../test/input.bin
```

Если хотя бы одно из имён не задано, программа завершается с кодом **10**.

### Формат входного файла

| Смещение, байт | Содержимое | Размер |
| --- | --- | --- |
| 0 | H — высота матриц A, B, C | 4 байта |
| 4 | W — ширина матриц A, B, C | 4 байта |
| 8 | A1, B1, C1, A2, B2, C2, …, AN, BN, CN (N = H·W) | по 1 байту |
| 8 + H·W·3 | DH — высота матрицы D | 2 байта |
| 10 + H·W·3 | DW — ширина матрицы D | 2 байта |
| 12 + H·W·3 | D1, D2, …, DN (N = DH·DW) | по 1 байту |

Значения матриц A, B, C идут вперемешку, а матрица D лежит отдельным блоком. Все матрицы хранятся построчно: элемент `X(k)` — это строка `(k−1) / W`, столбец `(k−1) % W`.

### Формат выходного файла

| Смещение, байт | Содержимое | Размер |
| --- | --- | --- |
| 0 | H | 4 байта |
| 4 | W | 4 байта |
| 8 | A'1, B'1, C'1, …, A'N, B'N, C'N | по 1 байту |

### Что нужно вычислить

Каждую из матриц A, B, C нужно свернуть с ядром D и получить A', B', C' того же размера H×W:

- центр ядра накладывается на каждый элемент матрицы, произведения соседних элементов на элементы ядра складываются. Ядро **не переворачивается**: D11 умножается на левого верхнего соседа;
- элементы за пределами матрицы считаются равными 0;
- если сумма больше 255, берётся её остаток от деления на 251;
- если сумма меньше 0, у неё меняется знак и берётся остаток от деления на 241.

### Ограничения и гарантии

- Порядок байт нативный для системы (примеры в little-endian).
- Все значения беззнаковые, кроме элементов D: это знаковые байты.
- DH и DW гарантированно нечётные.
- Решение — **один** исходный файл на C до 1 МБ, стандарт **C17**, компилятор **gcc**.
- Решение проверяется на закрытом наборе тестов, отдельно оценивается качество кода.
- Скрипт открытых тестов работает только на Linux и даёт программе **60 с** на тест. Успешный запуск должен вернуть код 0.

### Пример из условия

H = 4, W = 3. A = 1…12, B = 101…112, C = 201…212. Ядро D 3×3 со значениями 1…9:

```
A:  1  2  3      D: 1 2 3
    4  5  6         4 5 6
    7  8  9         7 8 9
   10 11 12
```

A'1 = 1·5 + 2·6 + 4·8 + 5·9 = 94 = `0x5e`.
B'1 = 101·5 + 102·6 + 104·8 + 105·9 = 2894 → 2894 % 251 = 133 = `0x85`.
Файлы примера: [open-tests/exmaple.in](open-tests/exmaple.in), [open-tests/exmaple.out](open-tests/exmaple.out).

## 2. Реализация

### Сборка и запуск

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -O2 matrixconv.c -o matrixconv
./matrixconv -i open-tests/exmaple.in -o out.bin
```

Отладочные сообщения в stderr включаются флагом `-DPRINT_DEBUG_INFO`.

Открытые тесты:

```bash
./open-tests/run-tests.sh ./matrixconv
# Passed all 12 tests
```

### Коды возврата

| Код | Значение |
| --- | --- |
| 0 | успех |
| 1 | не удалось открыть входной файл |
| 2 | некорректный вход: файл короче, чем заявлено; размеры не помещаются в память; чётное DH или DW |
| 3 | не хватило памяти |
| 4 | не удалось открыть или записать выходной файл |
| 10 | не заданы `-i`/`-o`, неизвестный флаг или флаг без значения |

### Структуры данных

```c
typedef struct {            // матрицы A, B, C размера h x w
    uint32_t h, w;
    uint8_t *data[3];       // data[0] = A, data[1] = B, data[2] = C
} image_t;

typedef struct {            // ядро D размера h x w
    uint16_t h, w;
    int8_t *data;
} kernel_t;
```

Типы фиксированной ширины совпадают с размерами полей в файле. Для D используется `int8_t`, а не `char`: знаковость `char` зависит от платформы.

Каждая из матриц A, B, C хранится в **своём** буфере, хотя в файле их значения перемешаны. Так внутренний цикл свёртки идёт по памяти подряд и хорошо векторизуется компилятором.

### Алгоритм

1. **`parse_args`** — ручной разбор `argv`. Поддерживаются формы `-i file` и `-ifile` в любом порядке. getopt не используется: он входит в POSIX, а не в C17, и со строгим `-std=c17` не компилируется.
2. **`read_input`**:
   - читает H и W и проверяет, что `H·W·3` помещается в `size_t` (`h > SIZE_MAX / 3 / w`, без переполнения в самой проверке);
   - **`image_alloc`** выделяет три буфера по H·W байт;
   - **`read_matrices`** читает файл **построчно** (W·3 байт) и раскладывает каждую строку по трём буферам.
   - читает DH и DW, проверяет их нечётность, затем одним `fread` читает D: ядро лежит в файле единым блоком байтов.
3. **`convolve`** вызывается трижды, по разу для A, B и C. Для каждой клетки `(row, col)` заранее вычисляются диапазоны строк `[i_from, i_to)` и столбцов `[j_from, j_to)` ядра, которые попадают внутрь матрицы. Значения за краем равны 0 и ничего не добавляют, поэтому их просто пропускаем, и во внутреннем цикле `sum += k[j] * s[j]` нет проверок границ.
4. **`normalize`** приводит сумму к 0…255 по правилам условия. Сумма хранится в `int64_t`: при ядре до 65535×65535 она достигает ~1.4·10¹⁴.
5. **`write_output`** открывает выходной файл только после успешной свёртки, поэтому при ошибке во входных данных файл не создаётся. Пишет H и W, затем **`write_matrices`** собирает строки `A'1 B'1 C'1 …` обратно и пишет каждую одним `fwrite`. Проверяются все `fwrite` и `fclose`.
6. **`main`** выполняет шаги цепочкой `if (rc == RC_OK)`, а память освобождается в одном месте. Все указатели либо выделены, либо `NULL`, поэтому очистка корректна после ошибки на любом шаге.

**Память:** 3·H·W (вход) + 3·H·W (результат) + DH·DW (ядро) + 3·W (буфер строки).

### Защита от некорректного входа

- Каждое чтение проверяется через `read_exact`: если файл короче заявленного, возвращается код 2.
- Переполнение размеров: `H·W·3` проверяется делением до умножения, а `DH·DW` вычисляется в `size_t`. Произведение двух `uint16_t` повышается до `int` и может переполниться, что является неопределённым поведением.
- Пустые матрицы (H = 0 или W = 0) - корректный вход: результатом будет только заголовок. Так как `malloc(0)` может вернуть `NULL`, выделяется минимум 1 байт.
- Индексы в свёртке знаковые (`int64_t`), а указатели строятся сразу на первый используемый элемент. Так не появляется указатель за началом массива.
- Лишние байты в конце файла игнорируются.

### Статический анализ

- **clang-tidy** выдаёт `clang-analyzer-optin.taint.TaintedAlloc` на три `malloc`: размеры берутся из файла. Переполнение исключено проверками выше, но верхний предел размера (например, по реальному размеру файла) не задан.
- **cppcheck** предлагает объявить `argv` в `parse_args` как константный (`constParameter`), это стилистическое замечание.
